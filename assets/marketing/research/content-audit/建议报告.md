## 用户目前经历的五步

1. **发现产品。** 官网解释长任务与 iPhone 实时活动，但主按钮首先引导 Agent/CLI 安装。
2. **判断可用性。** 首屏显示“App Store · 即将上线”；下载页说尚未公开下载，与实际商店矛盾。
3. **评估价值。** 商店是八张英文界面截图，没有解释利益点的标题；第二张主要是锁屏壁纸。
4. **尝试安装。** 快速开始先谈 Skill、sudo、doctor、JSON、项目 API 和 Shell 补全，配对位于后半段。
5. **寻找首次成功。** Agent 提示词明确只安装验证，不配对、不运行示例。这个执行边界可以保留，但页面必须承接到用户主动扫码、运行示例、在手机上确认结果。

当前路径的完成标志更多是“工具已安装”，真正的价值时刻是“离开终端，也看到了自己任务的进展和结果”。

## 定位与应保留的优势

**建议主定位：离开电脑，也知道任务跑到哪了。**

先服务于使用 Mac/Linux、需要等待构建/脚本/训练/实验、持有 iPhone 的开发者。AI Agent 用户是值得验证的切入人群，但不必让整个产品显得必须搭配某种 Agent。这个判断基于功能与场景，尚没有用户访谈或转化数据证明它是最大市场。

表达顺序：用户收益 → 真实画面 → 场景 → 接入方式 → 数据边界。保留现有浮标图标和 Apple 原生方向；当前无需优先重做品牌名字和图标。

| 现有表达 | 建议 |
| --- | --- |
| Keep every run in sight | 保留为品牌短句，旁边明确 scripts/builds/experiments，降低运动类产品联想 |
| 长任务进度，抬手就能看见 | 可作次级短句；主标题加“离开电脑”情境，避免暗示尚未提供的 Watch 客户端 |
| 原生接入 AI Agent | 明确通过 CLI/Skill 接入 Agent 发起的任务，不暗示自动识别所有 Agent |
| 隐私优先，自由掌控 | 具体说完整命令、源码和完整日志默认留本机，手机查看状态 |
| 一条命令看到进度 | 区分包装命令获得状态/结果，与配置进度源获得百分比/阶段/ETA |
| 零数据收集、任何数据都不上传 | 当前公开资料不支持这些绝对表述，不用作口号 |
| 实时、永不漏报、始终准确 | 避免绝对保证，系统展示受网络、机器运行和权限设置影响 |

ChatGPT 插件、尚未发布的 install.sh、中国大陆独立托管、手机远程控制不纳入现阶段公开主卖点。自托管也是进阶能力；当前官方 App 不能填写任意服务器地址，文案需明确自有构建等条件。

## 官网与安装页

建议首页结构：

1. 首屏一句收益、真实界面、清楚的“开始使用”和 App Store 入口，标明 iPhone + Mac/Linux。
2. 15–30 秒实际演示：启动任务，手机查看进度，收到结果。现有 CSS 实时活动示意和 OG 艺术图作辅助，核心证据来自目标公开版。
3. 三个具体情境：构建/测试；训练/实验；Agent 发起的任务。每个给实际接入入口与结果画面。
4. 首次使用：装 App → 装 CLI → 扫码 → 主动运行示例 → 手机上确认。
5. 信任和 FAQ：电脑需要保持运行吗、没有百分比怎么办、是否必须用 Agent、平台要求、同步什么、如何停止接收。
6. 重复下载和电脑端接入入口。

电脑访客适合二维码和终端步骤；手机访客先下载 App，再提示回到电脑接入。这是后续设计建议，本次未完成有效的手机宽度和真机验证。

快速开始只保留首次成功的必要步骤。Shell 补全、SDK 双环境、JSON schema、四种进度模式及恢复命令放进进阶文档。安装提示词提供复制入口与展开全文，不占据首页大段正文。

使用现有入口：准备系统依赖 → `uv tool install --python 3.12 runbuoy` → `runbuoy device pair` → 用户选择执行 `runbuoy demo live-activity` → 手机上确认。随后接入自己的任务。Agent 安装的权限边界保留，但最后明确给出配对的下一步。

不要先承诺“两分钟接入”，先记录干净环境中新用户的真实时间和失败点。

## 商店文案

美区副标题为 Keep every run in sight；中国区显示分类“效率”，未显示对应价值副标题。美区正文前有额外介绍段，中国区未展示；未读取 Connect，不能据此确认后台字段是否为空。两区正文均为同一份英文描述。

## 宣传素材与小范围验证

先做最小素材包：中英文六图；网页/社交 20–30 秒演示；1200×630 分享图；中英文发布短文；首次接入说明和 FAQ。

社交视频可以是电脑启动 → 离开电脑 → 手机状态更新 → 结果 → 下载。App Store 预览另按 Apple 要求，以设备录制的 App 体验为主体，不直接把大量终端/外景的社交广告当作商店视频。[Apple 预览说明](https://developer.apple.com/app-store/product-page/)

先找 10–20 位确有长任务的开发者。中文先选一个开发者社区或已有技术社群；英文结合已有开发者账号与 GitHub。具体渠道取决于你的现有受众，本次没有数据证明哪个渠道最好。先比较训练/构建与 Agent 任务两种示例，再决定是否扩大到 Product Hunt、Show HN 等渠道。

建议内部验收：10 位未参与开发的目标用户，至少 8 位能在说明引导下、无需逐步口述，配对并在手机确认第一条真实任务状态，记录耗时与卡点。这是可用性目标，不是当前已达成结果或统计意义的市场验证。

| 阶段 | 观察什么 | 证据要求 |
| --- | --- | --- |
| 理解 | 5 秒后能复述用途、平台和收益 | 直接复述，不能只问好不好看 |
| 下载 | 官网到商店、商店到首次下载 | 可优先用 Connect 可用分析；本次未取数 |
| 激活 | 是否完成 CLI、配对、首个任务 | 初期自愿测试；服务端收件不能代替手机实际显示 |
| 复用 | 一周内是否用于第二个自己的任务 | 自愿反馈或明确告知的产品指标 |

官网当前声明默认没有第三方分析。若后续添加统计，先确定最小数据、用途与告知，不为了宣发悄悄加入跟踪。
